1. 문제 발견

프로젝트는 아이디어가 아니라 문제에서 시작하며 좋아 보이는 아이디어를 먼저 정하면 그 아이디어를 지키기 위해 문제를 나중에 끼워 맞추게 되므로, 이 장에서는 해결책을 만들지 않고 문제만 모음

🚫 이 장에서는 아이디어를 만들지 않고 AI에게 처음부터 해결책을 물으면 문제가 실제로 존재하는지 확인하기 전에 해결책이 먼저 굳어짐. 아이디어 전환은 2장에서 진행

1.1 아이디어의 출발점

아래 세 경로 중 하나만 선택해도 되고, 팀원별로 서로 다른 경로를 맡아 병렬로 진행해도 무관하며 어느 경로를 택하든 1장의 결과물은 아이디어가 아니라 문제 목록이 도출되어야함

출발점던지는 질문의 형태이런 팀에 적합함
관심 주제이 영역에서 사람들이 반복적으로 불편해하는 일은 무엇인가다루고 싶은 분야가 정해진 팀
타겟 사용자이 사람들이 시간·정보·비용 때문에 곤란해지는 순간은 언제인가돕고 싶은 대상이 정해진 팀
최근 변화최근 달라진 행동이나 기술 때문에 새로 생긴 불편은 무엇인가분야도 대상도 아직 정해지지 않은 팀

실습 예시

  • 팀원 A · 관심 주제: 반려동물 헬스케어 → 반려인의 건강관리 과정 탐색
  • 팀원 B · 타겟 사용자: 소규모 음식점 운영자 → 하루 업무 흐름 탐색
  • 팀원 C · 최근 변화: 생성형 AI를 활용한 콘텐츠 제작 증가 → 검수·저작권·품질관리 문제 탐색

  • 문제 상황 하나에 집중
  • 핵심 기능 하나를 먼저 시험
  • 실시간 연동보다 복사·붙여넣기나 파일 입력 등 단순한 입력 방식 우선
  • 완성 서비스보다 핵심 가치가 보이는 프로토타입 우선

6.1 탈락 기준 적용

좋아 보이는 이유보다 지금 제외해야 할 이유를 먼저 확인해 조사와 구현에 사용할 시간을 보호

  • 실제 문제 근거가 약함
  • 타겟이 지나치게 넓거나 불명확함
  • 데이터·도구 접근이 현실적으로 어려움
  • 핵심 기능을 학기 안에 시연하기 어려움
  • 기존 대안과 차이가 거의 없고 추가 검증도 어려움

📝 활동내역 및 산출물

이번 주차부터 산출물을 팀 단위로 제출함

  1. 문제 목록과 팀 검증표(1.5) — 제외한 문제와 사유 포함
  2. 아이디어 정리표(2.3)
  3. 1차 후보 요약표·후보 비교표와 탈락 기준 판정 기록
  4. 시장·트렌드·타겟·기술 가능성 분석표
  5. 대학생 팀 프로젝트 수행 가능성 점검표
  6. 프로젝트 후보 카드 2개 (5~6주차에서 발전시킬 최종 후보)

단계별 완료 결과 체크

  • 문제 탐색 결과: 탐색 출발점과 문제 후보 목록이 정리되어 있음
  • 문제 검증 결과: 팀 경험으로 검증한 최종 문제 5~7개가 정리되어 있음
  • 아이디어 확장 결과: 검증된 문제에서 출발한 아이디어 15~20개가 정리되어 있음
  • 1차 후보 선정 결과: 분석할 후보 3~5개와 추가 조사 질문이 정리되어 있음
  • 가능성 분석 결과: 후보별 시장·트렌드·타겟·기술 분석 근거가 정리되어 있음
  • 수행 가능성 결과: 기간·팀 역량·데이터·도구 접근성·시연 가능성 판정이 정리되어 있음
  • 최종 선정 결과: 제외 후보와 사유, 최종 후보 2개, 프로젝트 후보 카드 2개가 완성되어 있음
  • 다음 주차 연결: 후보별로 7주차 최종 선택 전에 확인할 질문이 2개 이상 정리되어 있음

[참고]

4주차에서 선정한 두 후보는 아직 최종 프로젝트가 아니고, 우선 후보로 선정

  • 5주차: 두 후보의 목표 사용자·문제·AI 담당 구간을 구체화하고, 두 후보에 공통으로 사용할 팀 전용 AI 비서를 제작
  • 6주차: 텍스트·이미지·음성·영상·코드 등 멀티모달 활용 가능성을 시험하며 두 후보의 결과물이 어떤 형태로 나올지 각각 탐색
  • 7주차: 실제 사용자 검증과 핵심 기능 테스트를 통해 최종 프로젝트 1개 선택
