1. LLM 개념과 생성형 AI 작동 원리 이해

1.1 LLM이란 무엇인가

LLM(Large Language Model)은 방대한 텍스트와 코드에서 언어 패턴을 학습하고 입력된 문맥을 바탕으로 다음 토큰을 확률적으로 예측하며 결과를 생성하는 모델임

💡

LLM은 인간과 같은 방식으로 의미를 이해한다고 단정하기 어렵고, 복잡한 추론처럼 보이는 결과를 생성해도 사실성까지 자동으로 보장하는 것은 아님

1.2 Transformer

Transformer는 문장 속 여러 토큰의 관계를 병렬적으로 계산할 수 있어 대규모 언어 모델 학습에 적합한 구조임

Self-Attention

문장 안 각 토큰이 다른 토큰과 얼마나 관련 있는지를 계산하여 현재 문맥에서 중요한 관계를 반영하는 구조

Multi-Head Attention

여러 Head가 서로 다른 표현 공간에서 관계와 패턴을 동시에 살펴보는 구조이며 각 Head가 반드시 하나의 고정 역할만 담당하는 것은 아님

Layer와 FFN

Attention과 Feed-Forward Network를 포함한 블록을 여러 층 반복하며 입력 표현을 점차 정교하게 변환하는 구조

2. 토큰·컨텍스트·확률적 생성

2.1 토큰 수가 LLM 사용에 미치는 영향

토큰은 AI가 입력과 출력을 처리할 때 사용하는 정보 단위임. 프롬프트를 무조건 짧게 쓰기보다 필요한 목적·맥락·조건은 충분히 주고 관계없는 반복을 줄이는 것이 중요

영향설명사용 원칙
컨텍스트 사용량입력과 출력이 한 번에 다룰 수 있는 범위를 함께 사용함핵심 자료와 조건을 우선 제공함
응답 길이입력량과 서비스 조건에 따라 출력 여유가 달라질 수 있음원하는 출력 분량을 명확히 제시함
비용·처리량API에서는 토큰이 사용량·비용 기준이 될 수 있음불필요한 반복을 줄임

2.2 컨텍스트 창 — AI는 한 번에 얼마나 많은 정보를 볼 수 있을까

컨텍스트 창은 모델이 한 번에 참조할 수 있는 최대 범위로 대화 내용·첨부 자료·지시사항·생성 중인 답변 등이 함께 들어가는 작업 기억 공간에 해당함

현상설명대응
컨텍스트 소실범위를 벗어난 정보가 반영되지 않을 수 있음중요 조건을 다시 명시함
컨텍스트 오염잘못된 정보와 실패한 시도가 남아 영향을 줌필요하면 새 대화창에서 다시 시작함
지시 희석대화가 길어지면서 핵심 지시가 다른 정보에 묻힐 수 있음현재 입력에 핵심 지시를 재확인함

2.3 확률적 생성 — 왜 같은 질문에도 답이 달라질까

LLM은 저장된 정답을 그대로 꺼내는 방식이 아니라 다음 토큰 후보들의 가능성을 계산하고 선택하며 문장을 이어 가는 구조임. 따라서 동일한 질문에서도 표현·구성·사례가 달라질 수 있음

예시) “오늘 점심으로” 다음에 김치찌개 35%, 샌드위치 25%, 국밥 20%처럼 여러 후보가 존재할 수 있으며 선택된 토큰이 다음 예측의 문맥이 됨

참고) 온도(Temperature)

온도는 높은 확률 후보에 얼마나 집중할지, 낮은 확률 후보까지 얼마나 폭넓게 고려할지 조절하는 개념임. 일반적인 대화 화면에서는 직접 설정하지 않는 경우가 많으므로 개념 이해 수준으로 볼 것

3. 대화형 AI 인터페이스의 이해

대화형 AI는 질문을 입력하는 검색창이 아니라 작업에 맞는 기능을 선택하고 자료를 제공하며 결과를 반복 개선하는 작업 환경임

3.1 기본 사용 흐름

무엇을 할지 정하기 → 기능·자료 선택 → 질문 입력 → 결과 확인 → 추가 질문·수정 → 사실 검증

3.2 대화창 관리

  • 하나의 대화창에는 하나의 목적을 중심으로 관리함
  • 잘못된 정보나 실패한 시도가 많이 누적되면 새 대화창에서 핵심 조건을 다시 정리함
  • 반복 사용할 조건은 템플릿이나 설정으로 관리함

4. 프롬프트 5요소와 반복 개선 전략

4.1 프롬프트 5요소

복잡한 작업에서는 역할·목적·맥락·조건·형식을 구분해 제시할수록 모델이 요구사항을 파악하고 결과를 통제하기 쉬워짐. 단순한 질문에는 다섯 요소가 모두 필요한 것은 아님

요소핵심 질문
역할어떤 관점과 전문성을 사용할 것인가
목적왜 이 답변이 필요한가
맥락어떤 상황·대상·배경인가
조건무엇을 반드시 지키거나 제외해야 하는가
형식결과를 어떤 구조로 받을 것인가

4.2 반복 개선

초기 질문 → 결과 확인 → 부족한 점 1개 특정 → 수정 지시 → 개선 결과 비교 → 필요한 경우 재검증

5. 환각·편향·최신성 한계와 사실 검증

5.1 환각

환각은 모델이 학습한 패턴에 따라 그럴듯한 문장을 생성하는 과정에서 존재하지 않는 사실을 사실처럼 서술하는 현상임. 생성 과정·학습 데이터 한계·불확실성 처리 등 여러 요인으로 발생할 수 있음

5.2 편향

학습 데이터의 사회적 고정관념이나 다수 관점이 응답에 반영될 수 있으므로 반대 관점과 다른 근거를 함께 요청해 비교할 것

5.3 최신성

가격·정책·일정·최신 사건처럼 바뀌는 정보는 모델 내부 지식만으로 판단하지 않고 웹 검색이나 공식 원문을 확인할 것

5.4 사실 검증 4단계

주장 분리 → 출처 확인 → 원문과 내용 대조 → 확인·수정·삭제 판정
